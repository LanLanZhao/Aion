# 科研模块 v1：服务器连接与中转

日期：2026-11-21
状态：待确认

## 意图

在 Quest 的抽屉里新增「科研」入口，用来管理实验服务器连接。首版只做「能看到服务器、能新增、能验证连得上」，不做指标曲线和日志解析。

训练服务器不能跑自己的 HTTP 服务，手机也不能直接 SSH（Expo 没有现成 SSH 客户端），所以在用户自己的电脑上跑一个中转进程：它持有 SSH 凭据，替手机去连服务器，对手机只暴露普通 HTTP。

## 目标

- 抽屉「能力」和「项目」之间新增「科研」
- 服务器列表（名称、`user@host`、最近一次连通状态）
- 新增服务器、删除服务器
- 测试连接（SSH 真实登录并执行一条无害命令）
- 中转与 App 之间用一个 Bearer token 做最低限度鉴权
- SSH 凭据只存在中转（电脑上），App 不保存密码或私钥

## 非目标

- 指标曲线、loss 可视化、日志解析（下一版）
- 在手机上启动/停止训练
- 多用户、云同步、推送通知
- 公网暴露与 TLS（v1 只建议局域网或 Tailscale）

## 方案

### 中转（仓库内 `relay/`，Bun 进程）

- 启动：`bun run relay`，读取 `relay/relay.config.json`；首次启动自动生成 token 并打印
- 绑定地址默认 `0.0.0.0:8787`，文档里明确建议只在可信局域网或 Tailscale 下使用
- **不引入 `ssh2`**：直接调用系统 OpenSSH（Windows 10+ 自带，macOS/Linux 也有）。这样能复用电脑上已有的 `~/.ssh/config`、私钥、ssh-agent、跳板机配置，也避开了在 JS 里处理密钥口令
- 服务器表存在 `relay/data/servers.json`，keyPath 等字段不回传给 App

接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/health` | 中转存活 + 版本，供 App 验证地址和 token |
| GET | `/servers` | 服务器列表（脱敏） |
| POST | `/servers` | 新增服务器 |
| DELETE | `/servers/:id` | 删除服务器 |
| POST | `/servers/:id/test` | SSH 连接测试，返回耗时与错误 |
| GET | `/ssh-hosts` | 列出 `~/.ssh/config` 里的 host 别名 |

新增服务器的字段：

- 名称（必填，≤ 60 字）
- Host（必填；可从 `/ssh-hosts` 选，也可手填 IP/域名）
- 端口（默认 22）
- 用户名（必填）
- 私钥路径（可选，留空走 ssh 默认/agent）
- conda 环境名（可选，v1 只保存不使用）
- 实验根目录（可选，v1 只保存不使用）

### App

- 路由：`/research`（列表）、`/research/new`（新增）、`/research/relay`（中转地址与 token）
- 中转配置存在本机 `quest-research.json`（沿用项目的 `expo-file-system` 落盘方式）；v1 明文保存，后续可换 SecureStore
- 列表为空时引导「先连接中转」；卡片上的「测试」按钮触发 `/servers/:id/test`
- 长按卡片删除（二次确认）
- 抽屉新增一行，图标用 `FlaskConical`

## 关键取舍

- 用系统 `ssh` 而不是 `ssh2`：少一个依赖，直接继承用户已经配置好的登录环境；代价是每次调用要拼命令、做参数转义，且错误信息来自 stderr，需要归一化成可读文案
- 配置放在中转而不是 App：手机丢了不会泄露主机清单和私钥路径；代价是 App 必须能连上中转才能管理服务器
- 首版不做详情页和曲线：先把「连接」这条链路跑通，日志格式确认后再决定解析方案

## 错误处理

- 中转不可达：列表显示离线状态，可重试；不阻塞进入新增页
- token 错误：401 → 提示重新配置中转
- SSH 失败：区分超时、拒绝连接、认证失败、主机不存在，返回可读文案
- 测试连接超时 8 秒

## 验证

- 中转：`bun test`（字段校验、命令转义、servers.json 读写）
- App：`bun run typecheck`、`bun run test`、`bun run lint`
- 手工：PC 起中转，手机（同 Wi-Fi 或 Tailscale）配置地址和 token，新增服务器，测试连接，杀掉服务器上的 sshd 验证错误文案
